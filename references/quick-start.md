# skill-adapter 快速开始

## 一句话理解

把一个成功 skill（如 `/dbs`）的机制适配到新领域（如 Matt skills），完成从对标到交付的完整流程。

---

## 典型场景

### 场景 1：对标已有 skill 做新领域版本

**输入**：
> 我想做一个类似 `/dbs` 的 Matt 版智能路由，覆盖 24 个 Matt skills

**执行**：
```
/skill-adapter
```

**输出**：
- 分析 `/dbs` 的核心机制
- 识别 Matt skills 的特殊性
- 生成适配后的 `ask-matt-smart`
- 通过分级验证
- 交付可用 skill

---

### 场景 2：参考某个机制做类似工具

**输入**：
> 参考 `/dbs-jtbd` 的访谈机制，我想做一个产品需求分析工具

**执行**：
```
/skill-adapter
```

**输出**：
- 分析 `/dbs-jtbd` 的访谈框架
- 适配到产品需求场景
- 保留 JTBD 核心逻辑
- 调整问题清单
- 验证并交付

---

### 场景 3：克隆并本地化

**输入**：
> 我想把 `/grill-with-docs` 的机制用到我们公司的内部项目，需要适配我们的文档结构

**执行**：
```
/skill-adapter
```

**输出**：
- 分析 `/grill-with-docs` 的访谈流程
- 适配公司文档结构（GLOSSARY.md → 公司模板）
- 保留访谈机制
- 验证并交付

## 快速流程

### 1. 说出你的对标对象和目标

```
我想做一个类似 [原 skill] 的 [目标领域] 版本
```

例如：
- "我想做一个类似 `/dbs` 的 Matt 版智能路由"
- "参考 `/dbs-jtbd`，做一个产品需求分析工具"

### 2. skill-adapter 自动执行

**阶段 1：澄清对标与目标**
- 读取原 skill
- 分析核心机制
- 识别目标领域特殊性
- 确定保留/删除/新增的模式

**阶段 2：生成适配后的 Skill**
- 创建目录结构
- 适配 SKILL.md
- 创建发现脚本
- 创建 README.md

**阶段 3：分级验证**
- 等级 1：结构校验
- 等级 2：行为冒烟（6-8 个样本）
- 等级 3：留出/回归（2 个留出样本）
- 等级 4：安装交付（可选）

**阶段 4：生成交付报告**
- VERIFICATION.md
- DELIVERY-REPORT.md
- 本地安装说明

### 3. 得到可用的新 skill

```
~/.agents/skills/<new-skill-name>/
├── SKILL.md
├── README.md
├── VERIFICATION.md
├── DELIVERY-REPORT.md
├── test-samples.md
└── scripts/
    └── discover-script.py
```

## 输入最少信息

skill-adapter 需要：

**必需**：
- 对标对象（原 skill 名称或描述）
- 目标领域（要覆盖的范围）

**可选**：
- 新 skill 名称（会自动推荐）
- 特殊要求（需要保留/删除的功能）

**示例最少输入**：
```
对标：/dbs
目标：Matt skills
```

skill-adapter 会自动：
- 读取 `/dbs` 的 SKILL.md
- 扫描 Matt skills 目录
- 分析差异
- 生成适配方案
- 执行验证
- 交付报告

## 适配 vs 创建

| 场景 | 用什么 |
|------|--------|
| 已有成功案例，做新领域版本 | `/skill-adapter` |
| 从零创造全新 skill | `/dbs-skill-maker` |
| 简单功能扩展 | 直接修改原 skill |
| 理论研究 | `/dbs-theory-grounding` |

## 常见问题

### Q1：什么样的 skill 适合作为对标对象？

**适合**：
- 有清晰的核心机制（如五维筛选）
- 机制是通用的（可跨领域）
- 已经验证成功（有实际使用案例）

**不适合**：
- 机制太简单（如单一脚本）
- 高度领域特定（无法迁移）
- 尚未验证（不确定是否有效）

### Q2：适配后的 skill 能达到什么质量？

**等级 3（留出/回归）**：
- 结构完整
- 主要功能验证
- 无关键回归
- 可本地使用

**等级 4（安装交付）**（可选）：
- GitHub 发布
- `npx skills add` 安装
- 可分享给他人

### Q3：适配过程需要多久？

**典型时间**：
- 阶段 1（澄清）：10-15 分钟
- 阶段 2（生成）：15-20 分钟
- 阶段 3（验证）：20-30 分钟
- 阶段 4（交付）：5-10 分钟

**总计**：50-75 分钟完成等级 3 验证

### Q4：我需要懂原 skill 的所有细节吗？

**不需要**。skill-adapter 会：
1. 自动读取原 skill
2. 提取核心机制
3. 识别通用逻辑
4. 指导你保留/删除什么

你只需要：
- 说出对标对象
- 说出目标领域
- 确认关键决策
